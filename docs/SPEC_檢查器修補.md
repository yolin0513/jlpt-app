## 每一件的三段證據（回報時逐件附上；缺一段，統籌者驗收當成沒修）

1. **修正前紅**：用一個落在盲點上的樣本，證明修正前它真的放行（附回傳值與輸出）。
2. **修正後擋、理由對**：同一個樣本，修正後擋下，輸出講得出是哪一條、哪一類、哪一個單位。
3. **突變**：把修上去的那個判斷拿掉（在暫存複本、commit 之後），**只有**對應的那一種報不符；確認跑到的是改壞的那一版。

## 每一個修補都要做到的（這兩天四家各自踩過）

1. **先跑一次原樣的基準、確認是綠的**，才採信「改壞之後」的結果。暫存複本、拋棄式 worktree 不會帶著主工作區還沒 commit 的改動。
2. **實驗外殼：改動沒套上就不跑、不讀輸出**；跑之前刪掉舊輸出檔；外殼本身要驗過會拒絕沒造成的實驗。
3. **從真實入口重現**，不要用模仿迴圈的程式。
4. **真實原文當對照組是必要、不充分，還要有突變**（規則可能分大小寫、只認某一種寫法）。
5. **成對驗**（F3）。
6. **補的對照樣本要真的落在盲點上**：改回舊寫法照樣抓得到的樣本，等於沒守住。
7. **每個 commit 單獨看都要是綠的**。
8. **比對理由，不只比回傳值**；斷言「不見了」之前先確認它原本在。
9. **新增或擴大一道「對不上就停」的檢查，先拿真實資料跑一次，確認不誤擋**；並補一種「正常情況要放行」的樣本。
10. **盤點或驗證「它會不會擋」，要確認擋下的理由指向你造的那個情境**，不只看回傳值（JLPT：修正前 52 項不符裡，有 26 項「來源清空／刪掉」其實回 1，但擋下的是去重規則或別的規則、輸出沒點名那個來源——只看回傳值會把一半的格子誤算成「會停」；統籌者驗收 JLPT 時自己的第一版探測也掉進同一個坑：少填一個欄位，擋下的是「缺 dupOf」，不是我要驗的「有效 0 筆」）。
11. **幾條新規則各自單獨拿掉一次**，每一次只紅在自己那一種情境、而且每一組都紅，確認規則之間沒有互相掩護（JLPT 的交叉驗證）。
12. **用腳本改文件（STATUS 之類），寫回之前要有保護**：行數只准變多、原本的章節標題都要還在，否則不寫（JLPT：插入段落那一行漏接後半份，照原樣寫回會把 STATUS 後半整份截掉，是後面另一步的 assert 碰巧擋下）。
