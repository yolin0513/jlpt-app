## 2. 什麼算個資（照這份判；拿不準的歸「邊界」，不要自己決定）

所有條目都只算**真實的、連得到 Yolin 或他家人的**資料。你自己造的測試資料、標明是合成的範例、在講產品設計情境的敘述（「有長輩的家庭」）都不算。

判斷的精神（Yolin 2026-09-23 的判定，Dispatch 的解讀）：**「去過哪裡」「吃什麼、不吃什麼」「有什麼病」都不算；「誰、在哪一天、在哪裡」、錢、身分、憑證才算。**

**算（要回報）**

1. **財務數值**：金額、股數、持有的標的代號、扣款筆數、投資年數、總市值、報酬率、真實的花費紀錄。單獨出現的公開代號不算（0050 是公開的 ETF）；跟「Yolin 持有」「他的計畫」連在一起才算。
2. **住家，以及「哪一天在哪裡」**：
   - 住家（地址、社區、找得到門口的地標）、工作地點、學校——**不需要日期就算**。
   - 真實成行（過去或未來）的**日期＋地點**：日期具體到「哪一天」或「幾號到幾號」才算；只到月份、季節、年份的不算。**未來的行程＋具體日期最優先**——那段時間家裡沒人。
   - 從上下文推得出成行日期的也算（例如「昨天全家去了某處」，配上那一條紀錄的日期）；拿不準就列邊界。
3. **身分**：Yolin 與家人的真實姓名、年齡（具體歲數或出生年）；學校、系所、工作單位。「Yolin」這個代稱與 GitHub 帳號 `yolin0513` 不算（本來就公開）；阿公、阿嬤、長輩、小孩這類稱呼不算。
4. **識別資訊與憑證**：內網 IP、MAC、device id、帳號名稱、真實 email（noreply 除外）、本機使用者名稱、本機絕對路徑；**真實的 group／trip ID、邀請祕鑰、邀請碼（含畫面上的 QR code）——不論旁邊有沒有地名都算**，而且屬於下面的「憑證類」。
5. **使用紀錄**：學習或使用紀錄中能推出個人作息或程度的具體數字（作答數、連續天數、程度、固定哪幾天不在家吃、每天幾點在用）。

**憑證類（最優先）**：金鑰、token、邀請祕鑰或邀請碼、真實的 group／trip ID——只要它拿得來加入或讀取真實的資料（行程、照片、花費）。發現了就**先回報這一項，不要等整份做完**；不要貼出值，也不要自己換或刪（換掉會讓家人連不上，要 Yolin 決定）。

**不算（不必回報）**

- **行程地點**（Yolin 2026-09-23 判定）：地名、景點、店名、住宿名、「去過哪裡」——只要沒有具體到哪一天的日期、也沒有真實的 group／trip ID 跟它連在一起。
- **飲食限制**（Yolin 2026-09-23 判定）：葷素、五辛、忌口、食物過敏、少糖低鈉這類飲食要求，以及實際排過的菜單內容。
- **病名與診斷**（Yolin 2026-09-23 判定）：某人有什麼病、身心狀況、過敏——跟飲食限制同一類。
- 一般化的敘述（「有數檔」「買了很多年」「家裡有長輩」「明年要出國」）。
- 標明是合成的範例數字；自己造的測試資料與人名。
- 公開的市場或規格事實（例如 0050 在 2025 年的分割）。
- 第三方文獻作者、GitHub 帳號、官方專案信箱、GitHub 與 Anthropic 的 noreply。
- 開發過程的紀錄（「Yolin 2026-09-21 回覆」「整套跑了 32 分鐘」）——文件本身的日期不是「成行的日期」。
- 裝置型號與系統版本（device id 才算）。

**邊界（列出來、每一筆標「待 Yolin 判定」，不要自己決定）**，例如：

- 去識別化過的真實資料：先看裡面的日期是不是真實成行的日期——是，就照第 2 條算；分不出來，列邊界。
- 寫明某人信什麼宗教。
- 其他你拿不準的。

## 3. 範圍與做法

**範圍**：`git -c core.quotepath=false ls-files` 列出的**全部**追蹤檔（程式、測試、資料、文件、設定、圖片），加上「未追蹤、也沒被 `.gitignore` 擋掉」的檔——它們一個 `git add -A` 就會進 repo。**git 歷史不查**：歷史裡的東西要改寫歷史才拿得掉，那是另一個決定；你若剛好知道某筆已從現在的檔拿掉、但還在歷史裡，順手列在最後。

**列檔一定加 `-c core.quotepath=false`**：不加的話，中文檔名會被 git 加上引號、結尾不是副檔名，用副檔名篩就會漏（統籌者 2026-09-23 實際漏過一次：TripQuest 的圖片數成 107 張，實際是 323 張）。列完用目錄計數當對照組核一次總數。

**做法**（照順序；含 regex 或反斜線的搜尋碼用 Write 寫成檔再跑，不要經過 shell heredoc 或 `node -e`）：

1. **機械掃描**：照你做 v5 工單 U7 的方式跑四類公開前自查（金鑰、email、使用者名稱、本機路徑；對照組照舊，email 用合成樣本），但對象是**全部追蹤的文字檔**，不是只看新增行。再加你自己寫的樣式：IP、MAC、長串隨機字元（token、ID、邀請碼的樣子）、具體日期、帶「元」「NT$」「¥」「股」的數字。每個樣式都要先在一行自己造的樣本上命中，才算數。
2. **逐段讀高風險區**：`docs/STATUS.md` 裡轉述 Yolin 或 Dispatch 原話的段落、實機回報、使用者回饋、驗收或對帳的數字；`docs/` 底下其他文件的同類段落；README。個資最常夾在「照實記下 Yolin 說的話」裡——StockDiary 的前例就是這樣。**讀的時候只找 §2「算」的五類**；地名、飲食、病名的敘述直接跳過。
3. **測試資料與 fixtures**：逐一確認來源——是你自己造的，還是從真實資料（備份、匯出、實機）抄來或改來的。改過的（去識別化），查裡面剩下的東西有沒有落在 §2「算」的五類（特別是真實日期、姓名、金額、ID）。
4. **圖片**：先查每一批截圖是**哪支腳本、用哪份資料**產生的。腳本用的是自己造的資料 → 那一批整批判「不算」，抽看 3 張確認；來源不明或手動截的 → 逐張看，**只找**真實的金額、姓名、具體日期、QR code 或邀請碼（畫面上的地名不算）。JPEG 另外查 EXIF：GPS 位置＋拍攝時間同時存在，就是「地點＋日期」，照第 2 條算（寫一支只讀的小腳本；做不到就照實寫做不到，列出檔名）。
5. **設定檔**：`.claude/`、`workers/` 之類——列出有哪些識別用的欄位（例如帳號 ID、資料庫 ID），**不貼值**，判斷它算不算憑證類。

## 5. 不准做的事

- **不改任何檔**：找到的個資一個都不動；不刪、不改寫 git 歷史、不換任何金鑰或邀請碼。
- **普查結果不寫進 repo 的任何檔**（包括 STATUS 與這份工單）——一份「個資在哪一行」的清單放進 public repo，本身就是在指路。結果只放在回報裡。
- **回報裡也不要貼個資原文**：寫檔名、行號、類別、遮罩後的提示（例如「一筆五位數的金額」「某位家人的年齡」）。
- 不跑 `npm test`、不跑突變（這一份用不到）。
- 不要動其他 App 與統籌工作區的檔案。
