# SPEC：2026-09-03 功能候選清單中沒做的項目（草稿）

- **狀態**：規劃中，尚未動工。
- **背景**：2026-09-03 Yolin 列了一份功能候選，說「不必全做，選投資報酬率最高的幾項紮實完成」。
  v1.1.0 挑了 6 項（重點複習、跨級搜尋、朗讀、每日目標、快捷鍵、首次引導），以下 4 項沒做，也沒有逐一說明理由。
  這裡把它們整理成可以挑選的候選，由統籌者評估、Yolin 決定要做哪些。

## 1. 依詞性／主題篩選練習

> **詞性的部分已由 `docs/SPEC_詞性篩選.md` 取代並於 2026-09-21（v1.15.0）實作完成**；主題標籤仍未做（要替題庫加欄位，屬異動較大）。

- 現況：JLPT 單字有 `pos`（詞性）欄，但學習頁與 `buildSession` 都沒有詞性篩選；只有生活旅行的情境會話有「依情境挑選」。
- **依詞性**：直接用既有的 `pos` 欄，沿用 `buildSession` 的 `filter` 參數（v1.9.0 新增）。**小改動**。
- **依主題**：要替題庫加主題標籤，等於 JSON schema 新增欄位，**屬異動較大**，要投票。
- 建議：先做詞性篩選。

## 2. 假名輸入或拼寫測驗

- 現況：所有題型都是四選一或閃卡自評，沒有輸入題。
- 設計要點：手機要切日文鍵盤才能打假名，門檻高；`build_data.py` 自 v1.6.2 起會自動產生 `romaji` 欄，
  可以**接受羅馬字輸入再比對**，降低輸入門檻；判分要處理長音、促音的寫法差異（ou／oo、tch 等）。
- 不動資料結構，**小到中型改動**。

## 3. 測驗結果分享或匯出

- 現況：只有整份學習進度的 JSON 備份，沒有單次測驗或模擬考成績的分享。
- 模擬考成績已存在 `meta.examHistory`（最近 20 次），可以直接當資料來源。
- 零後端做法：Web Share API 分享文字摘要，或下載 CSV。**小改動**。

## 4. 每日目標提醒（推播）

- 現況：只做了每日目標（統計頁滑桿、首頁進度），沒有任何提醒機制。
- **技術限制**：沒有後端就不能做伺服器推播；Periodic Background Sync 只有部分瀏覽器支援且必須先安裝；
  iOS 網頁推播要先加入主畫面，還需要推播伺服器。**推播服務不得接需要付費或金鑰的外部服務**（Yolin 的規則），真的要做得先問。
- 零後端可行做法（尚未評估）：開 App 時顯示 App 內提示；或匯出每日重複的 `.ics` 行事曆提醒，讓手機行事曆負責提醒。
