## 共同做法

**取舊版**（照統籌者的做法）：
- 用**明確的 commit 雜湊**（修正那個 commit 的父 commit），不用會跟著本機變的 `origin/main`。
- 前置三項，全部先過才往下跑，任何一項不成立就中止：
  1. `origin` 真的是 GitHub（`https://github.com/…`，不是本機路徑——StockDiary 撞過 worktree 的 `origin` 指向本機 repo，「修正前」跑到的其實是新版）；先 `fetch`，舊 commit 在 `origin/main` 的歷史裡，而且是新版的祖先。
  2. 這件改到的每一支檔，新舊兩份的雜湊不同。
  3. 新加的那段判斷只在新版裡：舊版沒有、新版有（兩個方向都驗）。
- 在暫存 clone 裡跑的，clone 出來之後再斷言 HEAD 就是那個雜湊。

**比對**：
- 同一支（工作區的）測試對新舊兩版各跑一次（`--ref <雜湊>` 讓測試從那個 commit 取被測的程式）。
- **兩次的結果行數必須相同而且非空**才比——「相同」在母體是空的時候恆真（統籌者比對兩種順序時，用 `grep` 抽 ✓／✗ 兩邊都抽到 0 種，印出「相同（0 種）」）。
- 擋下的理由**只在錯誤訊息的位置比對**，不數「整份輸出有沒有出現」（統籌者驗 TripQuest 時，舊版輸出裡也出現過那個名稱，但那是清單在列城市名）：
  - `test_datacheck.py`：stderr 去掉「  ! 略過…」警告行；
  - `test_filters.py`：過濾器「停：」開頭那一行，以及「  x … → 理由」那一行；
  - `test_pushsafe.sh`：`PUSHSAFE:`／`SELF-CHECK `／`LINT-GATE ` 開頭，以及 lint 逐條報的固定縮排行；
  - 證據腳本：同上，另加驗法結果行（行首 `yes`／`no`）。
- 資料建置的每一格要三件事都成立：回傳值非 0、錯誤訊息點名這個單位、輸出目錄（`data/`，不含 `src`）的雜湊前後相同；**被別的規則碰巧擋下的（回非 0 但沒點名這個單位）一律算「沒擋」**。雜湊一個檔都沒掃到就中止。

## F8（`a05b1b1`）：先寫暫存檔，全部成功才換上

四家統一修法（統籌者 2026-09-24 以本 App 的 build_data 修法為底，加上這一條）。「先檢查再寫」擋資料有問題；這一條擋資料沒問題、寫到一半失敗（磁碟滿、檔案被鎖住），兩者互補。
- **做法**：`commit_outputs()`：每個輸出先寫成同目錄的 `.tmp`；任何一個寫失敗 → 刪掉已寫的暫存檔、一個都不換、點名那個檔、回非 0；全部寫成功才一個一個換上。換上這一步失敗時照實講出已換上幾個、沒換上幾個（這一步沒有做到原子，屬已知的殘餘風險）。真實資料重建後 `data/` 與重建前逐位元組相同（含 `dataVersion`）。
- **新情境 B-writefail**：母體是每一個輸出檔（13 組＋`search-index.json`＋`manifest.json`＝15 個），各當一次「寫它的時候失敗」。注入：包一層啟動器，讓 `Path.write_text` 寫到那個檔（或它的 `.tmp`）時丟 `OSError`，新舊兩版都經過同一個函式，所以同一個注入對兩版都有效；錯誤訊息故意不帶檔名，點名只能靠 build_data 自己；真的注入到了才寫一個記號檔，沒寫就中止（情境沒造成）。先把 15 個輸出檔都改成過期內容，只要有任何一個被寫成新的，雜湊就會變。
- **舊版**：`5e58810`。前置同上；`def commit_outputs` 舊版沒有、新版有。
- **修正前**：94 行 → **不符 15**，全是 B-writefail：第一個檔（`vocab/n5.json`）寫失敗時前面還沒寫任何東西，只有「錯誤訊息沒點名」；其餘 14 個還加上「data/ 被改動了」（一半新一半舊）。
- **修正後**：94 行不符 0。
- **突變**（2026-09-24，在暫存 clone commit 之後以 `--ref HEAD` 跑）：寫失敗時不清暫存檔 → B-writefail 14 項不符（留下 `.tmp`）；不分兩階段、每寫好一個就換上 → 14 項不符（一半新一半舊）；雜湊函式拿掉「一個檔都沒掃到就中止」→ 對照組（空的 `data/`）中止、回 2。
- **比對點名改成只看錯誤訊息區**的突變：改回看整份輸出 → 新對照組（警告行裡的組名不能算）報錯。
