## 0. 這件事分兩步，這一份只做第一步

Yolin 要的比「篩選」多：他要學到同一個字的各種變化（動詞的て形、ない形…，形容詞的活用）。實查：題庫 2,671 個單字**每一筆都有 `pos`（缺值 0）**，但只到大類；**全庫沒有任何活用資料，動詞也沒有分一類／二類／三類**。768 個動詞裡有 247 個（i／e 段＋る結尾）程式判不出類別，必須人工逐一標記——標錯 App 就會教錯的變化形。所以：

- **第一步（這一份）**：照詞性挑題目。資料現成，小改動。
- **第二步（另一份，統籌者之後寫）**：補動詞類別的資料 → 程式產生變化形 → 單字卡多一區「變化」＋一種新的練習。**這一份不要為第二步預留任何程式或資料欄位。**

## 1. 現況

- `pos` 的值與筆數：名詞 1,303、動詞 768、形容動詞 184、副詞 178、形容詞 164、接續詞 30、代名詞 22、連體詞 11、疑問詞 10、「名詞・副詞」1。文法（608 筆）與旅行（266 筆）沒有 `pos`。
- 篩選的掛點已經有：`session.js` 一般題庫分支的 `if (typeof o.filter === 'function') pool = pool.filter(o.filter)`；`quiz.js` 已經用它掛「漢字讀音」「例句填空」。**`flashcards.js` 呼叫 `buildSession` 時沒有傳 `filter`**；`learn.js` 的 `start()` 把 `type／level／mode／scope` 帶進 `/study` 的 query。
- 只有 `src='set'`（一般題庫）走得到 `o.filter`；複習、錯題本、收藏、弱點、旅行各有各的來源。
- 空題池已有 fallback（`quiz.js` 約 49 行）。

## 2. 規則

- **R1 學習頁多一排「詞性」**：只在 `type === 'vocab'` 時顯示（文法沒有詞性）。選項：**全部（預設）／動詞／い形容詞／な形容詞／名詞／副詞／其他**。畫面上用學習者熟悉的叫法「い形容詞」「な形容詞」，對應資料裡的「形容詞」「形容動詞」；「其他」＝接續詞、代名詞、連體詞、疑問詞。那一筆「名詞・副詞」在選名詞或副詞時都要出現。樣式沿用同一頁既有的分段選擇元件（級別那一排），不新增元件種類。
- **R2 每個選項旁邊顯示這一級這個詞性有幾個字**（例如「動詞 142」），數字從題庫實際算、不寫死。0 個的選項不顯示。
- **R3 選了詞性之後，從學習頁開始的測驗與閃卡都只出那個詞性**：`start()` 把 `pos` 帶進 query；`quiz.js` 與 `flashcards.js` 都把它變成 `filter` 傳給 `buildSession`。**和既有的題型篩選（讀音、填空）要能同時成立**（兩個條件都過才出題），不是後者蓋掉前者。
- **R4 範圍**：只作用在一般題庫（`src='set'`）。複習、錯題本、收藏、弱點、聽力、模擬考、旅行**不受影響**——那幾個入口不帶 `pos`，就算網址被人手動加了 `pos` 也不理（或照實篩，你選一種並寫進回報；重點是不能壞）。
- **R5 SRS 不變**：篩選只決定「這一輪從哪些字裡挑」，排序（到期優先、新題比例 `DUE_QUOTA`）照舊在篩過的池子上跑；答題結果照常寫進同一份進度。篩選不新增任何儲存的資料——除了 R6。
- **R6 記住上次的選擇**：比照 `lastLevel`，用既有的設定機制記 `lastPos`（放既有的 `meta`／設定，不動 IndexedDB schema——照你 STATUS §3.3 不算異動較大）。換級別後那個詞性在新級別是 0 個 → 退回「全部」。
- **R7 篩完題目很少時**：池子小於這一輪的題數 → 有幾題出幾題，不重複出、不報錯；0 題 → 走既有的空池畫面，文字照實（「N5 沒有這個詞性的字」之類，措辭你定）。
- **R8 測驗的干擾選項**：四選一的錯誤選項現在從哪個池子挑，請實查。如果選了「動詞」之後干擾選項還是混著名詞，題目會變得太簡單（看詞性就能刪掉）——**干擾選項優先從同一個詞性裡挑**，同詞性不夠 3 個才往外補。若現況已經是這樣就只要說明。

## 3. 不做的事

不動 `data/**`、不動 `build_data.py`、不新增資料欄位；不做主題標籤；不做「詞性變化」的任何畫面；不改 SRS 的算法；不改備份格式。
