# SPEC：備份提醒與持久儲存（草稿）

> **已由 `docs/SPEC_備份提醒.md` 取代**（2026-09-21，v1.14.0 實作完成）。以下內容保留原樣，僅供追溯。

- **狀態**：規劃中，尚未動工。
- **背景**：2026-09-03 跨級去重投票時，代理指出兩個風險，一直沒人接手：
  1. 使用者的學習進度**只存在他自己的瀏覽器 IndexedDB**，沒有後端、沒有任何可重建的副本。唯一的救命索是他自己按過「匯出學習資料」，**但 App 從不提醒他這麼做**。
  2. PWA 可能裝在多台裝置（或同一台的瀏覽器分頁與主畫面），每一份的 IndexedDB 各自獨立。
  另外，App 沒有呼叫 `navigator.storage.persist()`，瀏覽器在儲存空間不足時可能清掉資料（iOS 尤其積極）。
- **優先度建議**：中。成本低，但保護的是 Yolin 唯一、無法重建的資料。

## 草案（小改動，不動 IndexedDB schema）

1. **備份提醒**：在 `meta` 記 `lastExportAt`（匯出時寫入）。距上次匯出超過 N 天、且這段期間有學習紀錄時，在首頁顯示一張提醒卡，一鍵匯出。
2. **請求持久儲存**：App 啟動或第一次匯出時呼叫 `navigator.storage.persist()`（有支援才呼叫），統計頁顯示目前是否已取得持久儲存。
3. 兩者都只新增 `meta` key，**不動 IndexedDB schema，不算異動較大**（與模擬考成績 `examHistory` 同樣做法）。

## 待決問題（需 Yolin 決定）

1. N 取幾天？（建議 14 天。）
2. 提醒要不要能關掉？（建議：可以「本週不再提醒」，但不能永久關閉。）

## 驗收

- audit 補斷言：`lastExportAt` 超過 N 天且有新進度時首頁出現提醒；剛匯出後不出現；匯出不改動任何學習資料。
- 手機真機確認 `persist()` 的實際結果（併入 `SPEC_device_test.md`）。
