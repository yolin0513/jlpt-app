## 共同做法

**取舊版**（照統籌者的做法）：
- 用**明確的 commit 雜湊**（修正那個 commit 的父 commit），不用會跟著本機變的 `origin/main`。
- 前置三項，全部先過才往下跑，任何一項不成立就中止：
  1. `origin` 真的是 GitHub（`https://github.com/…`，不是本機路徑——StockDiary 撞過 worktree 的 `origin` 指向本機 repo，「修正前」跑到的其實是新版）；先 `fetch`，舊 commit 在 `origin/main` 的歷史裡，而且是新版的祖先。
  2. 這件改到的每一支檔，新舊兩份的雜湊不同。
  3. 新加的那段判斷只在新版裡：舊版沒有、新版有（兩個方向都驗）。
- 在暫存 clone 裡跑的，clone 出來之後再斷言 HEAD 就是那個雜湊。

**比對**：
- 同一支（工作區的）測試對新舊兩版各跑一次（`--ref <雜湊>` 讓測試從那個 commit 取被測的程式）。
- **兩次的結果行數必須相同而且非空**才比——「相同」在母體是空的時候恆真（統籌者比對兩種順序時，用 `grep` 抽 ✓／✗ 兩邊都抽到 0 種，印出「相同（0 種）」）。
- 擋下的理由**只在錯誤訊息的位置比對**，不數「整份輸出有沒有出現」（統籌者驗 TripQuest 時，舊版輸出裡也出現過那個名稱，但那是清單在列城市名）：
  - `test_datacheck.py`：stderr 去掉「  ! 略過…」警告行；
  - `test_filters.py`：過濾器「停：」開頭那一行，以及「  x … → 理由」那一行；
  - `test_pushsafe.sh`：`PUSHSAFE:`／`SELF-CHECK `／`LINT-GATE ` 開頭，以及 lint 逐條報的固定縮排行；
  - 證據腳本：同上，另加驗法結果行（行首 `yes`／`no`）。
- 資料建置的每一格要三件事都成立：回傳值非 0、錯誤訊息點名這個單位、輸出目錄（`data/`，不含 `src`）的雜湊前後相同；**被別的規則碰巧擋下的（回非 0 但沒點名這個單位）一律算「沒擋」**。雜湊一個檔都沒掃到就中止。

### F8 之二：清理那一步本身失敗（統籌者驗收時抓到）

- **統籌者的情境**：在 `n3.json.tmp` 的位置先放一個同名資料夾。原本的做法回 1、`data/` 正式輸出沒變、沒有檔被換上（做對的），但清理連寫失敗的那個路徑也去刪、刪不掉就在第一個例外中斷——輸出是 Python 錯誤堆疊、不是「點名是哪個檔」，已寫好的 4 個 `.tmp` 留在 `data/`。在 Windows 上防毒或索引程式鎖檔就會這樣。
- **做法**：清理逐個試，除了「檔案不存在」之外的失敗也接住、列進報告（「另有 N 個暫存檔清不掉、留在原地…」），最後一定走到點名那句。第一版多寫了一個「那個位置原本就有東西就不去刪」的分支，檢視後發現對資料夾刪不掉、對既有的檔刪掉也無害，拿掉以免留一個沒人守的分支。
- **新情境**（每個輸出檔都跑，不挑代表）：
  - **B-tmpdir**：15 個輸出檔，各在它的暫存檔位置先放一個同名資料夾（裡面有一個檔）。每一格：回非 0、錯誤訊息點名那個檔、沒有錯誤堆疊、`data/` 雜湊不變（資料夾還在、沒留下別的 `.tmp`）。
  - **B-cleanupfail**：寫某個檔失敗，而且第一個輸出（`vocab/n5.json`）的暫存檔刪不掉（注入 `Path.unlink` 丟 `PermissionError`，真的注入到才寫記號檔）。每一格：點名失敗的檔、也點名清不掉的那個暫存檔、沒有錯誤堆疊、正式輸出不變、留下的 `.tmp` 剛好只有那一個。14 個——第一個輸出不適用（它前面沒有已寫好的暫存檔）。
- **修正前**：`c0fbb7a`（`origin/main`）。`test_datacheck.py` 共 123 行 → **不符 29**：B-tmpdir 15、B-cleanupfail 14，全部是錯誤堆疊、沒點名，除了第一格之外都留下 `.tmp`。其餘 94 行都符合。
- **修正後**：123 行不符 0。真實資料重建 `data/` 零差異。
- **突變**：清理只接「檔案不存在」（改回修正前的寫法）→ 只紅 B-tmpdir 15、B-cleanupfail 14；清不掉的照樣收集但不報出來 → 只紅 B-cleanupfail 14（沒點名清不掉的暫存檔）。

### F8 之三：只清自己寫出來的暫存檔、換上失敗時退回（`08234cf`）

- **起因**：MealMate 中了同一個錯（`ERR_FS_EISDIR`），兩家獨立實作、同一個形狀；它的改法是「只清自己寫出來的暫存檔；清理失敗也點名、不中斷」，另把「換上失敗、清理也失敗」寫成一格。對照之後本 App 還差三處：F8 之二的清理仍會去刪「失敗的那個位置」，不管是不是自己建的（被佔住的資料夾會被報成「清不掉的暫存檔」）；換上那一步失敗時會留下一半新一半舊，而且沒有格子；「寫到一半失敗」只注入了「還沒建檔就失敗」，沒有「寫出半個檔才失敗」。
- **做法**（`commit_outputs()`）：
  - 暫存檔位置被非檔案佔住 → 先停、不動它、點名；
  - 從開始寫那一刻起，那個暫存檔就算自己的：寫出半個檔才失敗，也要清掉；
  - 換上前先把舊檔改名成 `.bak`；任何一個換上失敗 → 這一個放回去、先前換上的全部退回，再清掉自己的暫存檔、點名那個檔；退回本身失敗也逐個點名、照實講「一半新一半舊」；
  - 全部換上成功才刪 `.bak`（刪不掉只警告，不改回傳值）。真實資料重建 `data/` 零差異、沒留下 `.tmp`／`.bak`。
- **格子**（`test_datacheck.py` 共 153 行，每一類都是 15 個輸出檔逐一跑）：
  - B-writefail 改成「寫出半個檔才失敗」（注入先寫 `PARTIAL` 再丟錯）；每格加「不能是錯誤堆疊」。
  - B-tmpdir 加一條：不能把不是自己建的資料夾報成「清不掉的暫存檔」。
  - **B-replacefail**（新）：換上某個檔時失敗（注入 `Path.replace`）→ 回非 0、點名那個檔、沒有錯誤堆疊、`data/` 雜湊不變（含沒留下 `.tmp`／`.bak`）。
  - **B-replacecleanup**（新）：同上，而且那個檔自己的暫存檔刪不掉 → 另外點名它、正式輸出不變、留下的 `.tmp` 剛好只有它。
  - 被測的舊版若根本沒有「換上」這一步，注入不會發生 → 記成 `n/a`（不算洞、也不算過；只在 `--ref` 指舊版時允許，工作區版本遇到就中止）。
- **修正前**：`fd90180`（`origin/main`，F8 之二那一版）。153 行 → **不符 45**：B-replacefail 15（沒有退回、留下 `.tmp`）、B-replacecleanup 15（換上失敗後根本沒去清暫存檔）、B-tmpdir 15。**自己扣掉的**：B-tmpdir 那 15 格，舊版其實已經停下、`data/` 沒變、也點名了，差別只在把別人的資料夾報成「清不掉的暫存檔」——是訊息不準，不是資料安全的洞；照判準算不符，但不當成舊版在那裡有洞。所以真正的洞是 30 格（換上那一步）。B-writefail（寫出半個檔）、B-cleanupfail 舊版都符合。
- **修正後**：153 行不符 0。
- **突變**（暫存 clone 蓋上新版、改壞、commit，`--ref HEAD`）：
  - 不先擋被佔住的位置 → 只紅 B-tmpdir 15；
  - 寫成功才算自己的（半個檔不清）→ 只紅 B-writefail 15、B-cleanupfail 14；
  - 換上失敗不退回先前換上的 → 只紅 B-replacefail 14、B-replacecleanup 14（第一個輸出失敗時前面還沒換上任何東西，那一格本來就不會半新半舊）；
  - 換上失敗不把這一個的備份放回去 → 只紅 B-replacefail 15、B-replacecleanup 15；
  - 換上失敗後不清暫存檔 → 只紅 B-replacefail 15、B-replacecleanup 15。
- **殘餘風險**：退回那一步本身失敗（例如 `.bak` 放不回去）沒有造格子，只有照實點名；目前沒有辦法不靠假的檔案系統造出來。

## 跳脫掃描擴到全部腳本＋多跳脫規則＋孤兒檢查（`a5a8f85`）

統籌者補充說明（四）：heredoc 把反斜線吃掉的那種，寫的當下攔不到（本 App 那次變成語法錯誤，一執行就炸、反而安全）；真正會空轉的是語法正確、但 regex 被多跳脫了一次——只有掃描抓得到。所以不是要更小心，是把掃描的母體擴大，讓新寫的腳本下一次跑就會被掃到。
- **做法**（`scripts/lint_gate.py`，每次推送的第一步）：
  - 跳脫類兩種規則（`backslash` 舊有、`overescape` 新增）掃 **repo 裡全部 49 支腳本**（`ESCAPE_TARGETS`，登記制，含 App 的 `js/`、`sw.js`）；閘門三支照舊掃全部規則。
  - `overescape`：Python 用 `tokenize` 找字串——原始字串裡「兩個反斜線＋d/s/w/b」、一般字串裡「四個反斜線＋d/s/w/b」；JS 的 regex 字面（樣式近似）與字串；shell 的 grep／sed 那一行。
  - **孤兒檢查**：專案裡的腳本（追蹤中＋沒被 gitignore 的新檔）沒登記進 `ESCAPE_TARGETS` 的，報成 `escape-orphan`、擋下；登記了卻不存在的，報「讀不到登記的檔」、擋下。
  - 實際掃到的檔必須等於登記的聯集，不等就講明「檢查器壞了」。
  - 對照組：`overescape` 5 條（每種語言、每個分支各一條，全部當場組出來）、反例 2 條（正確的跳脫、比對字面反斜線的字元類）；跳脫孤兒檢查的對照組（兩支沒登記的新腳本必須被報、登記過的與非腳本不能報）。樣本與樣式都用 `chr(92)` 組出來，lint 自己的原始碼不會出現多跳脫的字面。
- **先拿真實資料跑**（§5.14）：現有 49 支 0 命中、0 孤兒。
- **舊版**：`c0fbb7a`（`origin/main`；與 `a5a8f85` 的父 commit 之間 `lint_gate.py` 沒改過）。前置：在 `origin/main` 歷史裡、是新版祖先；`lint_gate.py` 新舊雜湊不同；`ESCAPE_TARGETS`、`def r_overescape`、`def escape_orphans` 舊版沒有、新版有。
- **修正前／修正後**（暫存 clone、commit 之後跑；只看判定訊息行）：

| 情境 | 舊版 | 新版 |
| --- | --- | --- |
| 新增一支沒登記的腳本，內含多跳脫的 regex | 回 0，「LINT-GATE OK」 | 回 1，「命中（沒登記）：scripts/new_tool.py:0 [escape-orphan]」 |
| 已登記的一般腳本（`check_data.py`）寫入多跳脫的 regex | 回 0，「LINT-GATE OK」 | 回 1，「命中（沒登記）：scripts/check_data.py:280 [overescape]」 |
| App 的 JS（`js/kana.js`）寫入多跳脫的 regex 字面 | 回 0，「LINT-GATE OK」 | 回 1，「命中（沒登記）：js/kana.js:169 [overescape]」 |

- **突變**（新版上改壞、commit 之後跑）：`overescape` 規則回空 → 對照組報失效、回 1；跳脫孤兒檢查回空 → 對照組報失效、回 1；掃描清單改回只掃閘門三支 → 「實際掃到的檔（3 支）不等於登記的」、回 1。
