# SPEC：新增題庫內容的人工校對（草稿）

- **狀態**：規劃中，尚未動工。
- **背景**：
  - 2026-09-03 Yolin 指定的品質方向包括「尤其 N2/N1 例句品質」。Claude 在 v1.4.0 回報寫了「下一批規劃：N2/N1 例句品質抽查與潤飾」，
    隨即被 Yolin 插隊的「N5–N3 單字增補」取代，之後再也沒回頭做。
  - 之後內容大量增加，但人工抽樣數低於 Yolin 定的「每批至少 40 條」門檻：
    v1.7.1 N5–N3 文法 +116 點只抽 12 條；v1.7.2 N2/N1 單字 +493 條只抽 14 條；v1.10.0 全級別文法 +238 點的抽樣數沒有紀錄。
  - `check_data.py`、啟發式檢查、假名子序列檢查都通過，但**這些自動檢查抓不到「釋義不準」「例句不自然」「難度不符該級」**。
- **優先度建議**：中高。題庫錯了會讓使用者學錯，比題目少更糟（Yolin：「寧可慢一點也不要出錯」）。

## 範圍（依風險排序）

1. v1.7.2 新增的 N2／N1 單字（各約 240 條）
2. v1.10.0 新增的 N2（75 點）、N1（73 點）文法
3. v1.7.1、v1.10.0 新增的 N5–N3 文法
4. 其餘 v1.5.0 起新增的 N5–N3 單字（已抽過，可後排）

## 做法

- 每批至少 40 條，隨機抽（`python scripts/check_data.py --sample 40` 可輔助），逐條檢查：
  假名讀音、詞性、中文釋義是否準確、例句是否自然、例句難度是否符合該級、例句假名與中譯是否一致。
- **發現錯誤一律就地改那一行的欄位**（id 依有效資料列的順序編號，增刪資料列或把某一行改壞都會位移）；rebuild 後逐筆比對既有 id 的內容沒變（做法見 STATUS §5）。
- 改完跑 `build_data.py` → `check_data.py` → 三套測試 → commit、push → 線上驗證。
- 同時補完去重義項（STATUS §11 第 1 項的 3 筆）也可以放在同一批。
